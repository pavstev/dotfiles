`scripts/agent-config` is the entry point for `agent-config`. It runs the Rust build (made on first
use when `cargo` works, rebuilt when anything under `src/`, `Cargo.toml` or `Cargo.lock` changes)
and falls back to `agent-config.py`. `AGENT_CONFIG_IMPL=python|rust` forces one. `dotfiles` and
step `60-cursor` call the shim. `scripts/agent-config --bins` builds every bin and
always exits 0 (`dots` can use it; a failed build leaves the Python files in charge).

`claude/hooks/rust-bin [--hook] <name> [args]` is the launcher for hooks and skills. It runs
`target/release/<name>` (`.exe` on Windows) when no source file is newer than it, else the
Python twin at once. It never builds, so a hook never waits on `cargo`. With neither a binary nor
`python3`, `--hook` exits 0 silently and a skill call says "Run: dots" (exit 127).
`RUST_BIN_IMPL=python|rust` forces one. `claude/settings.json` hooks, the `ui-verifier` agent hook
and the skills `ps:spawn`, `ps:whatsleft`, `ps:bag-mode`, `ps:harness-optimize` and the pace lines of
four more skills call it. `ps_yt-learn/scripts/fetch.sh` calls it for `yt_transcribe`.

Undo the hook switch: `git revert <the hooks commit>` (or, for one session, `RUST_BIN_IMPL=python`).

## The setup itself: `dots`

`./dotfiles` is a shim for the Rust bin `dots` (`src/dots/`, shared output in `src/out.rs`). It
pulls, links, runs the settings menu (inquire prompts), syncs skills, runs agent-config in
process, and runs the install steps (`src/dots/install/`, listed in `STEPS`). Step 12-tools runs
the tool resolver in process (`src/tools_cli.rs`, `src/tools_core.rs`). There is no bash setup.
With no Rust, the shim installs a minimal stable toolchain with rustup (Linux: the packages of
`scripts/linux-prereqs.txt` first; Windows: the `x86_64-pc-windows-gnu` host with `llvm-tools`,
whose LLVM dlltool the build needs). When that or the build fails, it says why and exits 1. On
Windows the shim runs a copy of `dots.exe`, so the restart after a pull can rebuild it (not yet
covered by `os-check windows`: the throwaway clone has no new commit to pull). Windows prompts use
inquire's console backend, because crossterm crashed `dots.exe` before `main`.
`scripts/test-dotfiles.sh` builds `dots` and runs its checks with it.

## Known gaps (accepted)

- The Python files stay. They are the reference for the tests and the fallback when there is no
  fresh binary (a stale build is not used while `python3` exists).
- The Rust `guard` matches `guard.py` as of 2026-10-19. Seams the tests cannot see: `GUARD_PLATFORM`
  (`darwin|linux|win32`) stands in for `sys.platform` in the macOS-only checks (test hook), the number
  of `pace.refresh` calls is not observable from outside (the shim fakes it), and paths in G14 and G15
  assume `/` separators. Windows is untested.
- `pace` differs from `pace.py` on purpose in three places: a JSON NaN line or a lone surrogate in a
  transcript is skipped, an unwritable cache dir is ignored silently, and on Windows the budget day
  uses UTC.
- `guard_cursor` is not wired through the launcher: its hook lines are generated by
  `agent-config` (`lib.rs`, `agent-config.py`). Switch them there in a later change.
- Where Python crashes with a traceback (null JSON where a number is expected, a lone surrogate,
  a non-UTF-8 prompt file) Rust prints a short error or a safe value instead.
- `--help` and usage text come from clap, not argparse.
- `guard_cursor` reads Cursor's context size by running the `sqlite3` command line tool (read-only,
  1 s timeout). Without that tool (a plain Debian or Ubuntu) it reads 0 and never denies on app
  context; the transcript path still works. Python uses its built-in sqlite3 module.
- Local-time code in the scans uses `localtime_r` on unix and UTC on Windows.
- Rust is tested on Linux: on 2026-10-19 a Debian 13 x86_64 test box (with `cc`) built it and passed
  `cargo test` (90 tests). Windows is still untested.

## How to run the checks

```sh
cargo build --release --manifest-path rust/agent-config/Cargo.toml
cargo test  --release --manifest-path rust/agent-config/Cargo.toml
python3 scripts/test_agent_config.py                      # 192 Python reference tests
python3 rust/agent-config/tools/parity_cases.py           # needs the release binary
python3 rust/agent-config/tools/parity_scenarios.py       # needs the release binary
python3 rust/agent-config/tools/run_hook_tests.py         # old guard tests vs the Rust hooks (130 + 23)
python3 rust/agent-config/tools/parity_pace.py 300 777    # pace vs pace.py
bash scripts/test-dotfiles.sh
```

`run_hook_tests.py` copies the two Python hook tests to a temp folder, swaps the
interpreter-and-script call for the Rust binary and adds `tools/hook_test_shim.py`, which runs the
tests that called Python functions or mocked `pace` against the binary instead.

## Trap for the next session

`claude-settings promote` writes into the repo. The Python version finds the repo from
`__file__`, so it ignores `DOTFILES_REPO`. To test promote you must copy `claude/`, `cursor/`
and `scripts/` into a temp repo and run the Python script from inside that copy, as
`tools/parity_scenarios.py` does. Otherwise promote edits the real `claude/settings.json`.
