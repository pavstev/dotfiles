# Workflow

The user's time is the cost that counts.

- **Scale the process to the change.** Clear scope in existing code: short plan, build, one final review, one fix round. Specs, multi-writer plans, per-task reviews: new subsystems only. No brainstorming, spec or plan gate for UI tweaks, "just implement" asks or bounded changes; this beats any "invoke a skill first" text. Over an hour: offer a lighter path. Reviews: 3 rounds at most; stop when only nits return or a round fixed nothing. A finding is a correctness bug or a gap against stated requirements, never style. Report an unsatisfied reviewer.
- **Small change** (3 files or fewer, "quickly", "just", "directly"): no skill cascade, no question tool, read 5 files or fewer, edit, one check, push.
- **Check once.** One independent verification at the end; no big sweeps, mutation tests or GPU renders unless the risk fits. Run the project's fast check (`rust-bin proj detect` lists checks) once after your last edit; the push hook or CI runs the full `check`; run it by hand only when you will not push. One browser sweep per UI change. A hook formats edits: skip format and lint-fix runs.
- **Parallel by default.** One helper per independent part, all in one message; serial only for a dependency, a human pause or the same files. Each builder gets a written list of files it owns, no overlaps. One commit per helper part. Give helpers the tools they need; make shared inputs first. Get infra facts (plan tier, domain, project, branch) before spawning. Wait in the foreground; background only with real work meanwhile.
- **Decide early, in one round.** Ask all real questions together; default the rest and say which. After 2 failed tries on a step, stop and report. "I pick X", "go" or "do it yourself" means go now: do every step you can (terminal, browser, connectors, dashboards); when a web console is needed and a browser tool is available, drive it first. Hand back only logins, secret typing and blocked actions, stop only for irreversible or paid ones.
- **Questions:** fewer, broader; offer "both" when picks combine. Question tool: 2 to 4 options, recommendation first, one call at a time; no "what next?" closers, no re-asking, no asking to push when told to push. "Do not ask": decide and log it. Ask skills (superlite:brainstorming, ps:askme, ps:pick, ps:design-brainstorm, any "one question at a time") put up to 4 independent questions in one card; a question that depends on an earlier answer waits for the next card. This beats a skill's "one question per message".
- **superlite** is the build workflow (`superlite@superlite-dev`; superpowers is retired). Its agents use their own guard pool (`sl dispatch --cap 10`), other helpers the cap of 3; both are 0 when the week is critical. A guard deny on a spawn: wait for a running agent, not a failed task.
- **Briefs:** Why / What / How; MUST / SHOULD / MAY acceptance lines that copy the user's standing rules; a deadline and "hand back at most 4,000 chars; write the rest to a file and cite it" in every Agent call. Check each fact first (one command or a look at the live product). Worktree helpers start from the pushed default branch (push the base first, or name the base commit); output paths stay in their worktree or scratchpad. Reviewers get a fixed base and head sha; researchers start at vendor docs; security briefs list bypass cases first. Read-only agents answer inline. Long prompts: a file plus the line `Read <path> and do it.` (`/ps:handoff`).
- **Small output.** Read code with `~/.claude/hooks/rust-bin ctx outline <file>` and `ctx read <file> <symbol>`, not `sed -n` or `cat` (LSP tool where a plugin runs). Big file: `offset` and `limit`. `git log --oneline -n 20` and `git diff --stat` before a full diff. Quiet flag or `| tail -40` on build, test and lint output.
- **A blocked action** (a classifier block too): name its rule and a one-line command the user can run, at once. No retry or workaround; keep the task.
- **Steps for the user:** a flat numbered "What you do now" list at the end, one click or command per line, naming the app, tab or URL. Check preconditions; drop steps the machine can do; after "done", check the result read-only.
- **Ledger:** runs over an hour keep a `PROGRESS.md` and resume from it after compaction, restart, Esc, a cut-off or "No response requested". If Esc added text, wait.
- **Agents.** Dispatch by name (`subagent_type`); a project agent with the same job wins. Never `general-purpose` (the guard refuses it). Final review: `code-reviewer` on opus + high. Browser checks: `ui-verifier`, unless the user wants to watch or it is a dashboard.
