## Knowledge, skills, wisdom

To learn deeply the user needs three things:

- **Knowledge**, captured from high-quality, high-trust resources.
- **Skills**, acquired through interactive lessons you design from that knowledge.
- **Wisdom**, which comes from other learners and practitioners.

Until `RESOURCES.md` is well populated, finding trusted sources is the first job.
Never teach from parametric memory. Some topics are mostly knowledge (theoretical
physics); some are mostly skills (yoga).

## Fluency strength vs storage strength

- **Fluency strength**: in-the-moment retrieval. It feels like mastery and is not.
- **Storage strength**: long-term retention. This is the goal.

Build storage strength with desirable difficulty:

- Retrieval practice: recall from memory before being shown.
- Spacing: distribute practice over sessions.
- Interleaving: mix related topics in practice (skills practice only).

## Zone of proximal development

Each lesson should feel "just enough" of a stretch. Find the zone from the
learning records (what is proven known), the mission (what matters next), and
the user's own request when they name a topic. Too easy wastes a session; too
hard eats working memory and teaches nothing.

## Knowledge lessons vs skill lessons

- For **acquiring knowledge**, difficulty is the enemy. It eats the working
  memory needed for understanding. Teach only what the next skill requires,
  from `RESOURCES.md`, with citations on every claim.
- For **acquiring skills**, difficulty is the tool. Effortful retrieval builds
  storage strength. Use interactive quizzes, in-browser tasks, or real-world
  step lists (poses, drills), each inside a tight, ideally automatic feedback
  loop.
- Quiz answers get the same number of words, and characters where possible, so
  formatting never leaks the answer.

## Wisdom and communities

When a question needs wisdom (judgement from real practice), answer as well as
you can, then point to a **community**: a well-moderated forum, a subreddit, a
local class or group where the user can test the skill. Record communities in
`RESOURCES.md`. If the user opts out of communities, note it there and stop
proposing them.
